# RankWoven SaaS 核心頁面原型

更新日期：2026-07-25

## 1. 原型目標

本原型用於驗證 RankWoven SaaS 的三層核心資訊架構和工作流：前台展示頁、客戶後台、管理後台。它先使用前端靜態資料展示頁面形態，不接正式 API，不處理真實 CMS 寫入，不做真實登入與帳單。

## 2. 前台展示頁

| 路由 | 頁面 | 核心用途 |
|---|---|---|
| `/` | 功能簡介首頁 | 展示 AI SEO 審計、內容生成、圖片 SEO、內部連結、CMS 插件與多語言能力 |
| `/pricing` | 定價頁 | 展示 Starter、Growth、Agency、Enterprise 靜態套餐卡 |
| `/login` | 用戶登入頁 | 展示登入表單原型，並提供客戶後台與管理後台的靜態入口 |

前台頁面需要承擔品牌說明和轉化入口，但仍應直接展示產品能力，不做空泛的行銷頁。第一屏需要讓訪客立即理解 RankWoven 是自動 SEO 優化平台，並能進入定價或登入。

## 3. 客戶後台

| 路由 | 頁面 | 核心用途 |
|---|---|---|
| `/app` | 站點概覽 | 查看站點數、文章量、待審核建議、任務和 SEO 健康度 |
| `/app/sites` | 站點管理 | 管理 WordPress、Joomla、OpenCart 等站點連接狀態 |
| `/app/articles` | 文章審計 | 查看文章 SEO 分數、問題類型、優化機會和負責人 |
| `/app/article-sync` | 文章同步 | 從 CMS 同步文章、媒體、分類、作者與快照 |
| `/app/suggestions` | 處理建議 | 按文章、類型、優先級與就緒狀態處理 AI 建議 |
| `/app/media` | 媒體處理 | 審核圖片標題、圖片 Meta、Alt Text 與檔案名稱建議 |
| `/app/apply` | 一鍵套用 | 將已批准建議按批次套用並保留快照和回滾路徑 |
| `/app/article-suggestions` | 單篇文章修改建議 | 逐項審核單篇文章的內容、媒體和內鏈修改 |
| `/app/review` | 內容審核 | 對比現有內容和 AI 建議，保留人工批准流程 |
| `/app/links` | 內部連結 | 審核來源文章、目標文章、錨文本、推薦理由和信心度 |
| `/app/tasks` | 任務隊列 | 追蹤同步、審計、生成、圖片和發佈任務 |
| `/app/cms-adapters` | CMS 適配器 | 查看各 CMS 擴展階段和能力覆蓋 |
| `/app/settings` | 設定 | 管理 API、AI Provider、媒體存儲和團隊設定 |

客戶後台面向網站擁有者、內容負責人和 SEO 操作者，重點是站點接入、文章同步、建議處理、文章修改審核、媒體建議、一鍵套用、任務追蹤和 CMS 適配狀態。圖片標題與圖片 Meta 屬於媒體處理的一部分，不作為獨立客戶後台入口。

## 4. 管理後台

| 路由 | 頁面 | 核心用途 |
|---|---|---|
| `/admin` | 平台概覽 | 查看 MRR、客戶數、活躍站點、AI 成本、任務成功率和平台風險 |
| `/admin/customers` | 客戶管理 | 查看租戶、套餐、站點數、用量和客戶狀態 |
| `/admin/usage` | 用量與成本 | 追蹤 OpenAI、Google Gemini、DeepSeek、問問 API、七牛雲存儲等成本 |
| `/admin/operations` | 運營中心 | 監控失敗任務、Provider 延遲、審核積壓和每日系統檢查 |
| `/admin/settings` | 管理設定 | 配置套餐、Provider 路由、CMS 擴展開關、團隊權限和安全策略 |

管理後台面向 RankWoven 內部營運與技術管理人員，應比客戶後台更關注租戶、成本、隊列、風險與平台級配置。

## 5. 設計取向

- 採用左側導航、頂部工具列、主工作區的後台布局。
- 優先呈現表格、狀態、進度與審核操作，避免行銷式大 Hero。
- 所有頁面保留空間給後續 API 接入、Loading、空狀態和錯誤狀態。
- 所有新增顯示文案走 `vue-i18n`，目前以 `zh-Hant` 和 `en` 作為第一批文案。
- 原型資料均在頁面內存中定義，後續可逐步替換為 API Response 類型。
- 前台、客戶後台、管理後台以 `route.meta.layout` 區分布局，避免三種導航混在一起。

## 6. 後續吸收方向

- 將 `/login` 替換為真實認證流程，並按角色進入 `/app` 或 `/admin`。
- 將頁面內的靜態資料替換為 `src/api/` 請求。
- 建立共用 `DataTable`、`StatusPill`、`ProgressBar` 和 `PageHeading` 元件。
- 為文章審核頁接入差異對比、快照和回滾操作。
- 為任務隊列接入 Worker 進度事件和錯誤重試。
- 為管理後台補充租戶詳情、成本告警、Provider Key 狀態和管理操作日誌。
