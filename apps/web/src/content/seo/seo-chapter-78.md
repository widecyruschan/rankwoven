> 網站改版是 SEO 最危險的時刻之一。一個錯誤的 301 可以讓你好幾年的 SEO 努力化為烏有。這份 SOP 讓你安全過渡。

---

## 改版前必須理解的核心原則

### SEO 改版三大黃金法則

```
法則一：URL 能不改就不改
  → 改版 ≠ 一定要改 URL
  → 只改設計和內容，URL 保持不變 = 風險最低

法則二：改 URL 就一定要 301
  → 每個舊 URL 都要有一個對應的 301 轉址
  → 不要讓任何舊 URL 變成 404

法則三：不要建立轉址鏈
  → 舊 URL → 中間 URL → 新 URL ❌
  → 舊 URL → 新 URL（直接 301）✅
  → 每個轉址環節損失約 10-15% 的連結權重
```

## Phase 0：改版前準備（改版前 2-4 週）

### 任務一：建立完整 URL 清單

```
步驟 1：匯出所有現有 URL
  ┌─────────────────────────────────────────┐
  │ 方法 A：Screaming Frog 爬取              │
  │   → 爬取整個網站                         │
  │   → 匯出所有 200 狀態碼的 URL            │
  │   → 匯出所有有機流量的 URL（連接 GSC API） │
  │                                          │
  │ 方法 B：GSC 匯出                         │
  │   → 成效報表 → 按「網頁」分組            │
  │   → 篩選過去 16 個月（最大化範圍）        │
  │   → 匯出所有有點擊的 URL                 │
  │                                          │
  │ 方法 C：GA4 匯出                         │
  │   → 著陸頁報表                          │
  │   → 篩選有機流量                         │
  │   → 匯出所有有流量的 URL                 │
  └─────────────────────────────────────────┘

步驟 2：合併三個來源的 URL → 去重 → 得到完整清單

步驟 3：為每個 URL 加上以下資訊：
  - 過去 12 個月的有機流量
  - 反向連結數量（從 Ahrefs/Majestic）
  - 目前的排名關鍵字
```

### 任務二：URL 優先級分類

```markdown
🔴 P0 — 高優先級（有流量 + 有連結）
   → 必須 1:1 對應 301 轉址
   → 逐個驗證、不能有任何閃失
   → 這些是你的 SEO 核心資產

🟡 P1 — 中優先級（有流量但無連結，或相反）
   → 必須有 301 轉址
   → 可以群組規則處理（如整個目錄）

🟢 P2 — 低優先級（無流量、無連結）
   → 理想有 301，但如果內容已不存在
   → 至少確保不返回 404（返回 410 或 301 到相關頁面）
```

### 任務三：建立 URL 對應表（Mapping）

```
這是改版最重要的文件。格式：

舊 URL                              → 新 URL                       優先級  流量/月  連結數
────────────────────────────────────────────────────────────────────────────────
/old-blog/seo-tips/                → /blog/seo-complete-guide/     🔴 P0   2,340    15
/old-blog/keyword-research/        → /blog/keyword-research-2026/  🔴 P0   1,890    8
/products/old-product-name/        → /products/new-product-name/   🟡 P1   450      3
/old-category/                     → /new-category/                🟡 P1   2,100    12
/about-us-old/                     → /about/                       🟢 P2   120      0
```

**URL 對應表原則：**
- 每個舊 URL 都要有一個對應的新 URL（或明確標記為刪除）
- P0 URL 必須手動逐個確認對應
- P1/P2 URL 可以使用規則（如整個目錄對應到新目錄）
- 這份文件是改版的「聖經」，所有人員都要對齊這份文件
```

## Phase 1：開發/測試環境（改版前 1-4 週）

### 任務四：確保測試環境不被索引

```
☐ robots.txt 設定為 Disallow: /（測試環境）
☐ 使用 HTTP 基本驗證（密碼保護）
☐ 或限制 IP 訪問（只允許公司內部 IP）
☐ 確認 Google 無法訪問測試環境
```

### 任務五：測試環境中的 SEO 檢查

```
☐ 確認所有 301 轉址在測試環境中正常運作
☐ 使用 Screaming Frog 爬取測試環境
   → 上傳舊 URL 清單為「List Mode」
   → 確認每個舊 URL 回傳 301（不是 404、不是 302）
   → 確認 301 目標回傳 200
☐ 檢查 Canonical 標籤指向新 URL
☐ 檢查內部連結都指向新 URL（不殘留舊 URL）
☐ 檢查結構化資料在新頁面中正確
```

## Phase 2：上線日（D-Day）

### 上線前 1 小時：最後檢查

```
☐ 最終確認 URL 對應表已更新到最新版本
☐ 確認所有 301 轉址規則已部署
☐ 快速抽查 20 個 P0 URL：
   打開舊 URL → 確認 301 到正確的新 URL → 新 URL 返回 200
☐ 確認 robots.txt 是正式環境版本（不是 Disallow: /）
☐ 確認新網站沒有 noindex 標籤
```

### 上線後立即（第一個小時）

```
☐ 立即用 Screaming Frog 爬取舊 URL 清單
   → 確認所有 P0 URL 返回 301
   → 確認 301 目標返回 200
   → 如果有 P0 URL 返回 404 → 緊急修復 🔴

☐ 提交新的 Sitemap 到 GSC
☐ GSC → 設定 → 地址變更（如果是域名變更）
   → 通知 Google 網站已遷移

☐ 檢查 GA4 即時報表
   → 確認新網站有流量
   → 確認轉換事件正常觸發

☐ 手動請求首頁和主要頁面建立索引
   → GSC → 網址檢查 → 請求建立索引
```

### 上線後 24 小時

```
☐ 監控伺服器 Log（有大量 404 嗎？）
☐ 檢查 GSC 索引報表（有新頁面開始被索引嗎？）
☐ 檢查 Google 搜尋結果（site:example.com）
☐ 修復任何發現的問題
```

## Phase 3：改版後監控（第 1-4 週）

### 第 1 週：密集監控期

```
每日檢查：
☐ GSC 成效報表：流量有沒有異常？
☐ GSC 索引報表：舊頁面逐漸被新頁面取代？
☐ 伺服器錯誤日誌：有沒有 404 或 500？
☐ GA4 即時報表：流量正常嗎？

特別注意：
⚠️ 流量突然暴跌 30%+ → 可能有大量 404 或轉址問題
⚠️ 索引頁面數異常 → 可能 noindex 殘留或 canonical 問題
⚠️ 404 數量暴增 → 轉址規則有遺漏
```

### 第 2-4 週：穩定觀察期

```
每週檢查：
☐ GSC 成效比較（改版前 vs 改版後）
☐ 關鍵字排名變化
☐ 舊 URL 在搜尋結果中是否逐漸被新 URL 取代
☐ 行動版可用性報告
☐ Core Web Vitals 報告（新網站速度可能不同）

預期現象（正常）：
✅ 改版後 1-2 週可能有短暫的流量波動（Google 重新評估）
✅ 舊 URL 在搜尋結果中需要 1-4 週才會被新 URL 取代
✅ 排名可能暫時微幅波動

紅旗警報（不正常）：
🔴 流量持續下跌不回升
🔴 大量頁面未被索引
🔴 排名大幅下滑超過 2 週
```

## 特殊情境：域名遷移（Domain Migration）

### 域名遷移的額外步驟

```
☐ 新域名 GSC 驗證
☐ GSC → 設定 → 地址變更（從舊域名變更到新域名）
   注意：兩個域名都需要在同一個 GSC 帳號中驗證
☐ 舊域名的所有 301 正確指向新域名
☐ 聯絡主要外部連結來源，請他們更新連結到新域名
☐ 更新所有社群媒體簡介、目錄清單中的連結
☐ 更新 Google 我的商家中的網站連結

建議：保留舊域名至少 12 個月，並維持 301 轉址
```

## 常見改版 SEO 錯誤 Top 5

| 排名 | 錯誤 | 後果 | 避免方法 |
|------|------|------|----------|
| 1 | 忘記設定 301 轉址 | 大量 404，SEO 資產歸零 | 用 URL 對應表逐個確認 |
| 2 | 測試環境的 robots.txt 帶到正式環境 | 整個網站被 Google 封鎖 | 上線前雙重檢查 |
| 3 | 新網站忘記移除 noindex | 所有頁面無法被索引 | 搜尋代碼中的 "noindex" |
| 4 | 內部連結沒有更新 | 使用者點到 404 | 用爬蟲檢查內部連結 |
| 5 | 沒有通知 Google | 延遲索引更新 | 提交 Sitemap + 地址變更 |
