> 網站改版係 SEO 最危險嘅時刻之一。一條錯嘅 301 可以令你幾年嘅 SEO 努力化為烏有。呢份 SOP 等你安全過渡。
>
> 香港常見嘅改版情境有四種：① 換設計但唔換 URL（最安全）、② 由 `.com` 轉 `.hk`／`.com.hk`、③ 公司改名換域名、④ 由舊 CMS 搬去 Shopify / SHOPLINE / WordPress。每種風險唔同，但核心 SOP 一樣。

---

## 改版前必須理解的核心原則

### SEO 改版三大黃金法則

```
法則一：URL 能不改就不改
  → 改版 ≠ 一定要改 URL
  → 只改設計和內容，URL 保持不變 = 風險最低

法則二：改 URL 就一定要 301
  → 每個舊 URL 都要有一個對應的 301 轉址
  → 不要讓任何舊 URL 變成 404

法則三：不要建立轉址鏈
  → 舊 URL → 中間 URL → 新 URL ❌
  → 舊 URL → 新 URL（直接 301）✅
  → 每個轉址環節損失約 10-15% 的連結權重
```

> 🇭🇰 **香港額外法則：改域名唔好淨係改 Google。**
> 香港本地引用（GBP、OpenRice、TripAdvisor、Facebook、IG、小紅書、HKTDC、商會目錄、電郵簽名、名片、WhatsApp Business）全部都要改。呢啲 NAP 引用錯咗，本地排名會直接跌，而唔少公司改版後只記得改網站。

## Phase 0：改版前準備（改版前 2-4 週）

### 任務一：建立完整 URL 清單

```
步驟 1：匯出所有現有 URL
  ┌─────────────────────────────────────────┐
  │ 方法 A：Screaming Frog 爬取              │
  │   → 爬取整個網站                         │
  │   → 匯出所有 200 狀態碼的 URL            │
  │   → 匯出所有有機流量的 URL（連接 GSC API） │
  │                                          │
  │ 方法 B：GSC 匯出                         │
  │   → 成效報表 → 按「網頁」分組            │
  │   → 篩選過去 16 個月（最大化範圍）        │
  │   → 匯出所有有點擊的 URL                 │
  │                                          │
  │ 方法 C：GA4 匯出                         │
  │   → 著陸頁報表                          │
  │   → 篩選有機流量                         │
  │   → 匯出所有有流量的 URL                 │
  │                                          │
  │ 方法 D（香港必做）：Bing Webmaster Tools  │
  │   → Yahoo 香港 ~3-6% 用 Bing 索引        │
  │   → 匯出 Bing 嘅 URL 清單一併對照        │
  └─────────────────────────────────────────┘

步驟 2：合併來源的 URL → 去重 → 得到完整清單

步驟 3：為每個 URL 加上以下資訊：
  - 過去 12 個月的有機流量
  - 反向連結數量（從 Ahrefs/Majestic）
  - 目前的排名關鍵字
  - 語言版本（zh-HK / en-HK / zh-CN）
```

### 任務二：URL 優先級分類

```markdown
🔴 P0 — 高優先級（有流量 + 有連結）
   → 必須 1:1 對應 301 轉址
   → 逐個驗證、不能有任何閃失
   → 這些是你的 SEO 核心資產
   → 香港例子：「中環 裝修 報價」呢類地區頁、
     有 HK01 報導連結嘅頁面

🟡 P1 — 中優先級（有流量但無連結，或相反）
   → 必須有 301 轉址
   → 可以群組規則處理（如整個目錄）

🟢 P2 — 低優先級（無流量、無連結）
   → 理想有 301，但如果內容已不存在
   → 至少確保不返回 404（返回 410 或 301 到相關頁面）
```

### 任務三：建立 URL 對應表（Mapping）

```
這是改版最重要的文件。格式：

舊 URL                              → 新 URL                       優先級  流量/月  連結數
────────────────────────────────────────────────────────────────────────────────
/old-blog/seo-tips/                → /blog/seo-complete-guide/     🔴 P0   2,340    15
/old-blog/keyword-research/        → /blog/keyword-research-2026/  🔴 P0   1,890    8
/products/old-product-name/        → /products/new-product-name/   🟡 P1   450      3
/old-category/                     → /new-category/                🟡 P1   2,100    12
/about-us-old/                     → /about/                       🟢 P2   120      0
/zh/服務/                          → /zh-hk/services/              🔴 P0   1,200    6
/en/services/                      → /en-hk/services/              🟡 P1   680      4
```

**URL 對應表原則：**
- 每個舊 URL 都要有一個對應的新 URL（或明確標記為刪除）
- P0 URL 必須手動逐個確認對應
- P1/P2 URL 可以使用規則（如整個目錄對應到新目錄）
- 多語言網站：每個語言版本要分開對應，**唔好將 zh-HK 嘅 URL 301 去 en-HK**
- 這份文件是改版的「聖經」，所有人員都要對齊這份文件
```

## Phase 1：開發/測試環境（改版前 1-4 週）

### 任務四：確保測試環境不被索引

```
☐ robots.txt 設定為 Disallow: /（測試環境）
☐ 使用 HTTP 基本驗證（密碼保護）
☐ 或限制 IP 訪問（只允許公司內部 IP）
☐ 確認 Google 無法訪問測試環境
☐ 確認測試環境唔係用緊正式域名嘅子域
   （例：唔好用 test.example.hk，改用內部域名）
```

### 任務五：測試環境中的 SEO 檢查

```
☐ 確認所有 301 轉址在測試環境中正常運作
☐ 使用 Screaming Frog 爬取測試環境
   → 上傳舊 URL 清單為「List Mode」
   → 確認每個舊 URL 回傳 301（不是 404、不是 302）
   → 確認 301 目標回傳 200
☐ 檢查 Canonical 標籤指向新 URL
☐ 檢查內部連結都指向新 URL（不殘留舊 URL）
☐ 檢查結構化資料在新頁面中正確
☐ 檢查 hreflang 三個語言版本互相指向正確
☐ 檢查 GA4 / GTM 代碼已放上新站（唔好上線後先發現冇數據）
☐ 檢查 WhatsApp / 電話 / 地圖連結（香港主要 CTA）
```

## Phase 2：上線日（D-Day）

### 上線前 1 小時：最後檢查

```
☐ 最終確認 URL 對應表已更新到最新版本
☐ 確認所有 301 轉址規則已部署
☐ 快速抽查 20 個 P0 URL：
   打開舊 URL → 確認 301 到正確的新 URL → 新 URL 返回 200
☐ 確認 robots.txt 是正式環境版本（不是 Disallow: /）
☐ 確認新網站沒有 noindex 標籤
☐ 確認 SSL 憑證已安裝並生效
☐ 確認 .hk DNS 已指向新伺服器（TTL 建議事先調低）
```

### 上線後立即（第一個小時）

```
☐ 立即用 Screaming Frog 爬取舊 URL 清單
   → 確認所有 P0 URL 返回 301
   → 確認 301 目標返回 200
   → 如果有 P0 URL 返回 404 → 緊急修復 🔴

☐ 提交新的 Sitemap 到 GSC
☐ 提交新的 Sitemap 到 Bing Webmaster Tools
   （Yahoo 香港 + Copilot 索引）
☐ GSC → 設定 → 地址變更（如果是域名變更）
   → 通知 Google 網站已遷移
☐ Bing WMT → Site Move（域名變更時）

☐ 檢查 GA4 即時報表
   → 確認新網站有流量
   → 確認轉換事件正常觸發（WhatsApp / 電話 / 表單）

☐ 手動請求首頁和主要頁面建立索引
   → GSC → 網址檢查 → 請求建立索引
```

### 上線後 24 小時

```
☐ 監控伺服器 Log（有大量 404 嗎？）
☐ 檢查 GSC 索引報表（有新頁面開始被索引嗎？）
☐ 檢查 Google 搜尋結果（site:example.hk）
☐ 到 hk.yahoo.com 檢查 Yahoo 香港索引情況
☐ 修復任何發現的問題
☐ 更新香港本地引用（見下）
```

### 香港本地引用更新（最容易漏！）

```
☐ Google 商家檔案（GBP）網站連結更新
☐ OpenRice 商戶網站連結（餐飲）
☐ TripAdvisor 商戶資料（旅遊/酒店）
☐ Facebook 專頁 / Instagram 個人檔案連結
☐ 小紅書（RED）專頁連結
☐ LinkedIn 公司頁面網站欄
☐ HKTDC、香港中華總商會、商會目錄、黃頁
☐ Google Ads / Meta Ads 落地頁網址（唔好忘記廣告！）
☐ 電郵簽名、名片、WhatsApp Business 目錄
☐ 印刷品／包裝上面嘅 QR code（如有）
```

## Phase 3：改版後監控（第 1-4 週）

### 第 1 週：密集監控期

```
每日檢查：
☐ GSC 成效報表：流量有沒有異常？
☐ GSC 索引報表：舊頁面逐漸被新頁面取代？
☐ 伺服器錯誤日誌：有沒有 404 或 500？
☐ GA4 即時報表：流量正常嗎？
☐ GBP 洞察：曝光/來電/導航有冇異常下跌？

特別注意：
⚠️ 流量突然暴跌 30%+ → 可能有大量 404 或轉址問題
⚠️ 索引頁面數異常 → 可能 noindex 殘留或 canonical 問題
⚠️ 404 數量暴增 → 轉址規則有遺漏
⚠️ 英文版食咗繁中版流量 → hreflang 出錯
⚠️ 香港本地搜尋（地區 + 服務）排名跌 → GBP / NAP 未更新
```

### 第 2-4 週：穩定觀察期

```
每週檢查：
☐ GSC 成效比較（改版前 vs 改版後）
☐ 關鍵字排名變化（含地區長尾關鍵字）
☐ 舊 URL 在搜尋結果中是否逐漸被新 URL 取代
☐ 行動版可用性報告
☐ Core Web Vitals 報告（新網站速度可能不同）
☐ Bing Webmaster Tools 索引與點擊

預期現象（正常）：
✅ 改版後 1-2 週可能有短暫的流量波動（Google 重新評估）
✅ 舊 URL 在搜尋結果中需要 1-4 週才會被新 URL 取代
✅ 排名可能暫時微幅波動

紅旗警報（不正常）：
🔴 流量持續下跌不回升
🔴 大量頁面未被索引
🔴 排名大幅下滑超過 2 週
🔴 GBP 資料被標為「已結束營業」或被停用
```

## 特殊情境一：域名遷移（Domain Migration）

> 香港常見：`.com` → `.hk` / `.com.hk`（提升本地信任）、公司改名換域名、收購合併後統一域名。

### 域名遷移的額外步驟

```
☐ 新域名 GSC 驗證（建議用「網域資源」+ DNS 驗證）
☐ GSC → 設定 → 地址變更（從舊域名變更到新域名）
   注意：兩個域名都需要在同一個 GSC 帳號中驗證
☐ Bing Webmaster Tools → Site Move
☐ 舊域名的所有 301 正確指向新域名（逐頁對應，唔好全部
   淨係 301 去新首頁）
☐ 聯絡主要外部連結來源，請他們更新連結到新域名
   （香港常見來源：香港01、經濟日報、商會網站、合作夥伴）
☐ 更新所有社群媒體簡介、目錄清單中的連結
☐ 更新 Google 商家檔案中的網站連結
☐ 更新電郵域名（如 @old.com → @new.hk）
☐ 通知客戶與合作夥伴（香港 B2B 特別重要）

建議：保留舊域名至少 12 個月，並維持 301 轉址
     （最好長續，因為舊名片、舊印刷品、舊貼文嘅連結
      可以好多年後仲有人撳）
```

## 特殊情境二：平台搬遷（CMS / 電商平台轉換）

> 香港常見：WordPress → Shopify／SHOPLINE、自建站 → SHOPLINE、Magento → Shopify Plus。

```
☐ 確認新平台支援自訂 URL 結構（唔好被迫用 /products/123）
☐ 確認新平台可以改 robots.txt（部分 SaaS 限制好大）
☐ 確認新平台可以自訂 canonical / hreflang
☐ 匯出舊平台所有 Blog 文章 URL（Blog 通常係 SEO 主力）
☐ 確認新平台嘅 Sitemap 結構（有啲平台會自動分拆）
☐ 檢查新平台嘅預設 noindex（有啲平台測試模式會全站 noindex）
☐ 確認 GA4 / GTM 可以放到新平台（SHOPLINE 部分方案限制）
☐ 確認 301 轉址功能（部分平台只支援有限數量嘅轉址規則，
   超出就要用 Cloudflare / 伺服器層處理）
☐ 檢查新平台嘅 CDN 有冇香港／亞太節點
```

## 常見改版 SEO 錯誤 Top 5

| 排名 | 錯誤 | 後果 | 避免方法 |
|------|------|------|----------|
| 1 | 忘記設定 301 轉址 | 大量 404，SEO 資產歸零 | 用 URL 對應表逐個確認 |
| 2 | 測試環境的 robots.txt 帶到正式環境 | 整個網站被 Google 封鎖 | 上線前雙重檢查 |
| 3 | 新網站忘記移除 noindex | 所有頁面無法被索引 | 搜尋代碼中的 "noindex" |
| 4 | 內部連結沒有更新 | 使用者點到 404 | 用爬蟲檢查內部連結 |
| 5 | 沒有通知 Google | 延遲索引更新 | 提交 Sitemap + 地址變更 |

### 香港網站額外常見錯誤

| 錯誤 | 後果 | 避免方法 |
|------|------|----------|
| 只改 Google，冇改 Bing WMT | Yahoo 香港 + Copilot 索引失效 | Sitemap 兩邊都提交 |
| hreflang 冇跟住改 | 英文版食咗繁中版流量 | 改版後用檢查工具驗證 |
| GBP / OpenRice 網址冇更新 | 本地排名跌、用戶撳去舊址 | 列一張本地平台清單逐個改 |
| 廣告落地頁仲指住舊 URL | 廣告費浪費 + 用戶 404 | 改版日同步改 Ads |
| 用 SaaS 平台但冇 301 功能 | 舊 URL 全部 404 | 改版前先確認平台限制 |
