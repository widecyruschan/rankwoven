## 什麼是國際 SEO？

**國際 SEO（International SEO）** 是針對不同國家和語言的受眾，優化網站的策略。它不只是多語言翻譯，而是涉及**地理定位、當地搜尋引擎、文化差異、技術架構**等全面策略。

```
多語言 SEO vs 國際 SEO 的關係：

多語言 SEO = 用不同語言服務不同語言的受眾
國際 SEO   = 在不同國家/地區的搜尋引擎中獲得排名

  → 一個網站可以只有一個語言，但需要國際 SEO
    （例如：全英文網站，想在香港、新加坡、英國排名）

  → 一個網站可以有多語言，但不需要國際 SEO
    （例如：香港網站只服務香港，但提供繁中和英文）

實際上兩者通常一起進行：
  國際 SEO + 多語言 SEO = 在不同國家用當地語言獲得排名
```

## Google 的地理定位機制

Google 如何判斷一個網站（或頁面）的目標國家？

### 訊號 1：ccTLD（國家頂級域名）— 最強訊號

```
香港網站：
  yoursite.hk → Google 自動定位為香港內容

其他範例：
  yoursite.com.au → 澳洲
  yoursite.co.uk → 英國
  yoursite.sg → 新加坡
  yoursite.jp → 日本

⚠️ 注意：
  .com、.org、.net 等通用域名不會自動進行地理定位。
```

### 訊號 2：hreflang 標籤

hreflang 告訴 Google 頁面的語言和地區目標。詳見第 53 章。

### 訊號 3：Google Search Console 的地理定位設定

```
如果你的域名是 .com 等通用域名，
你可以在 Search Console 中手動設定目標國家：

Search Console → 舊版設定 → 國際目標 → 選擇目標國家

⚠️ 注意：
  → 這個設定只對 .com 等通用域名有效
  → .hk 域名無需設定（自動定位香港）
  → Google 正在逐步淘汰這個設定，現在可能已經找不到
```

### 訊號 4：伺服器位置（影響較小）

```
伺服器在香港 → 微弱的香港訊號
伺服器在美國 → 不一定代表美國目標

Google 官方說：伺服器位置不是主要的地理定位訊號。
但為了效能，建議目標國家的使用者訪問時使用 CDN。
```

### 訊號 5：當地反向連結和內容

```
來自香港網站的連結 → 香港定位訊號
內容提到香港、使用港幣、提及本地事件 → 香港定位訊號
```

### 三種架構選擇回顧

| 架構 | 範例 | 地理訊號 | SEO 權威集中度 | 成本 |
|------|------|---------|-------------|------|
| **ccTLD** | .hk / .sg / .jp | 🔥🔥🔥🔥🔥 | 分散 | 高 |
| **Subdirectory** | .com/hk/ / .com/sg/ | 🔥🔥 | 集中 | 低 |
| **Subdomain** | hk.site.com | 🔥🔥🔥 | 半分散 | 中 |

### 香港商家的國際 SEO 常見場景

#### 場景 1：香港品牌進入中國內地市場

```
方案推薦：
  → 簡體中文版使用 /zh-cn/ 子目錄（或獨立 .cn 域名如果法規允許）

特殊注意：
  ✅ 中國內地的搜尋引擎格局：百度主導、Google 不可用
  ✅ 需要針對百度做 SEO（Baidu SEO）而非僅針對 Google
  ✅ 需要在中國內地備案（ICP 備案）才能穩定營運
  ✅ 內容需要符合中國法規（這是國際 SEO 的法律層面）
  ✅ 關鍵字使用簡體中文，搜尋意圖和香港繁體使用者不同
```

#### 場景 2：香港品牌進入東南亞市場（新加坡、馬來西亞）

```
方案推薦：
  → 使用 .com 主域名 + /sg/、/my/ 子目錄

內容策略：
  ✅ 新加坡：英文為主（Singlish 口語化內容加分）
  ✅ 馬來西亞：英文 + 馬來文，視目標族群
  ✅ 每個國家獨立的在地化內容（不只是語言。
  ✅ 強調當地付款方式、運送政策等實用資訊
```

#### 場景 3：香港品牌進入英文市場（英國、美國、澳洲）

```
方案推薦：
  → .com 主域名 + /uk/、/us/、/au/ 子目錄
    或獨立 ccTLD（如果預算充足）

注意：
  ✅ 英文內容的在地化差異：
     colour (UK) vs color (US)
     lift (UK) vs elevator (US)
     dental surgery (UK) vs dental office (US)
  ✅ 每個國家獨立的 Google Search Console 屬性
  ✅ 價格顯示當地貨幣
```

## 國際關鍵字研究

### 不同國家的同一關鍵字，搜尋意圖可能完全不同

```
關鍵字：「牙醫 價錢」

香港 Google 結果：
  → 私人牙科診所價格比較
  → 政府牙科服務收費

新加坡 Google 結果：
  → CHAS 津貼下的牙科服務價錢
  → Medisave 能否用於牙科

英國 Google 結果：
  → NHS dental charges 2026
  → Private dentist fees UK

→ 同一個中文詞彙，不同地區的使用者想知道完全不同的東西！
```

## 國際 SEO 的技術層面

### CDN（內容傳遞網路）

```
為什麼國際 SEO 需要 CDN？

  速度就是排名因素：
  如果你的伺服器在香港，澳洲的使用者訪問你的網站，
  延遲可能高達 200-400ms。這會影響 Core Web Vitals 和排名。

CDN 推薦：
  → Cloudflare（全球最大的 CDN，有免費方案）
  → Fastly
  → Akamai（企業級）
  → AWS CloudFront

設定策略：
  → 使用 CDN 將網站內容快取到全球節點
  → 確保 CDN 不會阻擋 Googlebot（設定正確的白名單）
  → 不要對 Googlebot 做地理定向（讓 Googlebot 看到所有語言版本）
```

### Googlebot 的地理爬取

```
重要概念：
  Googlebot 主要從美國 IP 爬取你的網站。
  這意味著，如果你的網站對不同國家的 IP 顯示不同內容
  （地理定向/IP 定向），Googlebot 可能只看到美國版本。

Google 的建議：
  ❌ 不要基於 IP 自動重定向（例如：新加坡 IP → 自動跳到 /sg/）
  ❌ 不要對 Googlebot 隱藏其他國家的內容
  ✅ 使用 hreflang 標記所有語言/地區版本
  ✅ 提供清晰的語言/國家選擇器
  ✅ 如果需要基於 IP 給建議，使用橫幅（Banner）而非重定向
```

### 多地區價格與貨幣顯示

```
技術建議：
  → 使用 HTML 標記價格而非 JavaScript 動態生成
  → 確保 Googlebot 可以爬取所有貨幣版本的價格
  → 不要對不同國家的使用者顯示完全不同的價格頁面結構

結構化資料：
  → 在 Schema 中使用 priceCurrency 屬性標記貨幣
  "priceCurrency": "HKD"
  "priceCurrency": "SGD"
```

## 非 Google 搜尋引擎的國際 SEO

### 百度（中國內地）

```
百度 SEO 的基本原則（與 Google 的關鍵差異）：

  收錄速度：
    → 使用百度站長平台提交 Sitemap（https://ziyuan.baidu.com/）
    → 百度對新網站的收錄速度比 Google 慢很多

  技術要求：
    ❌ 百度不支援 hreflang
    ✅ 百度偏好靜態頁面（少 JavaScript）
    ✅ 中國內地伺服器（或香港）提升爬取速度
    ✅ 需要有 ICP 備案
    ❌ 百度不支援 JSON-LD Schema（但有自家格式）

  內容要求：
    ✅ 字數通常比 Google SEO 要求的更多（2,000 字+）
    ✅ 原創內容極度重要（百度對重複內容比 Google 更嚴格）
    ✅ .cn 域名和中文內容有先天優勢
```

### Bing（全球第二大）

```
Bing SEO 的注意事項：

  → Bing 使用 Bing Webmaster Tools（類似 Search Console）
  → hreflang 支援程度與 Google 接近
  → Bing 的排名因素更看重社群媒體訊號
  → Bing 對較舊的網站和 .edu/.gov 域名有偏好
```

### Yandex（俄羅斯）、Naver（韓國）

```
如果你的目標市場包括這些國家：

Yandex（俄羅斯）：
  → 有自己的 Webmaster Tools
  → 極度看重用戶行為訊號（點擊率、停留時間）

Naver（韓國）：
  → 搜尋結果大量使用 Naver 自家產品（Blog、Cafe、Knowledge iN）
  → 傳統 SEO 在韓國效果有限，需要經營 Naver 生態
```

## 國際 SEO 的內容策略

### 不要只翻譯，要在地化（詳見第 53 章）

### 在地反向連結策略

```
國際反向連結的建立：

目标市場：新加坡

  ✅ 與新加坡本地的合作夥伴交換連結
  ✅ 在新加坡行業媒體上獲得報導
  ✅ 贊助或參加新加坡的本地活動
  ✅ 與新加坡的 KOL/部落客合作
  ✅ 在新加坡商會登記

目標市場：英國

  ✅ 在英國行業目錄中登錄
  ✅ 英國本地媒體的公關曝光
  ✅ 與英國大學/研究機構的合作（獲權威連結）
  ✅ 參與英國的專業協會

每個國家的反向連結生態不同，不能統一複製。
```

### 在地社群訊號

```
社群媒體的地域差異：

香港 → Facebook、Instagram、WhatsApp
中國內地 → 微信、小紅書、抖音
日本 → LINE、Twitter
韓國 → KakaoTalk、Naver
歐美 → Instagram、TikTok、LinkedIn（B2B）

→ 在目標市場的主流社群平台上有存在感
→ 社群媒體訊號對部分搜尋引擎（Bing、Yandex）有直接影響
```

## 國際 SEO 的常見陷阱

| 陷阱 | 問題 | 解決方案 |
|------|------|---------|
| 自動 IP 重定向 | Googlebot 只看到一個版本 | 使用橫幅建議 + hreflang |
| 所有語言共用一個 Sitemap | 無法分別追蹤每個語言版本的索引情況 | 每個語言版本獨立 Sitemap |
| 忽略百度（如果做中國市場） | 在中國完全沒有搜尋流量 | 獨立制定百度 SEO 策略 |
| 在翻譯中使用 Google Translate | 低品質內容，可能被懲罰 | 專業翻譯 + SEO 在地化 |
| 不設定 hreflang x-default | Google 自行選擇預設版本 | 始終設定 x-default |
| 所有國家共用一個聯絡頁面 | 使用者體驗差、信任度低 | 每個目標國家獨立聯絡資訊 |
| 使用參數（?lang=en）而非路徑 | Google 不建議，SEO 效能差 | 使用路徑 /en/ 而非參數 |
| 忽略當地法規 | 網站可能在目標國家無法訪問 | 研究當地的隱私法、內容法規 |

## 國際 SEO 的路線圖

### 階段 1：研究與規劃

```
☐ 確認目標國家/地區（最多 3-5 個開始）
☐ 分析每個目標市場的搜尋量、競爭度
☐ 研究當地搜尋引擎生態（Google 主導？還是百度/Naver？）
☐ 研究當地競爭對手的 SEO 策略。
☐ 選擇架構（ccTLD / Subdirectory / Subdomain）
```

### 階段 2：技術實施

```
☐ 建立目標國家/地區的 URL 結構
☐ 實施 hreflang 標籤
☐ 為每個國家/語言建立獨立 Sitemap
☐ 設定 CDN
☐ 設定 Search Console 屬性（每個國家獨立）
```

### 階段 3：內容與連結

```
☐ 為每個目標市場進行獨立關鍵字研究
☐ 優先翻譯和在地化核心頁面（首頁、服務、關於我們）
☐ 建立每個市場的在地化部落格內容
☐ 開始建立當地反向連結
☐ 在當地社群媒體上建立存在感
```

### 階段 4：監控與迭代

```
☐ 追蹤每個國家/語言的關鍵字排名
☐ 監控每個國家/語言的搜尋流量
☐ 檢查 hreflang 錯誤（Search Console）
☐ 根據數據調整內容和策略
☐ 考慮擴展到新的目標市場
```
