## 什麼是 NAP？

**NAP** 是三個元素的縮寫：

| 字母 | 代表 | 說明 |
|------|------|------|
| **N** | Name（商家名稱） | 你的商家在法律上和公開呈現的名稱 |
| **A** | Address（地址） | 商家的實體地址或服務區域 |
| **P** | Phone（電話號碼） | 客戶可以直接聯繫你的主要電話 |

NAP 一致性（NAP Consistency）是本地 SEO 的**核心基礎**——在所有線上平台、目錄和網站上，你的 NAP 資訊必須**完全一致**。

```
想像 Google 的角色：

Google 在網絡上「爬取」你的商家資訊時，
它像是在做一份調查問卷：

  🔍 網站上的 NAP：新鴻基大廈 12 樓 A 室
  🔍 OpenRice 上的 NAP：新鴻基大厦 12/F, Unit A  ← 不一致！
  🔍 Yelp 上的 NAP：新鴻基大廈 12A ← 又不一致！
  🔍 Facebook 上的 NAP：電話 1234 5678 ← 網站上是 1234-5678！

Google 的結論：
  ❌ 這些資訊不一致，這個商家可能不可靠。
  ❌ 降低在地搜尋排名。
```

> **一句話總結：** NAP 不一致 = Google 認為你的商家資訊不準確 = 你失去排名和客戶。

---

## 為什麼 NAP 一致性如此重要？

### SEO 的影響

NAP 一致性直接影響：

1. **Google 對商家的信任度**：當 Google 在多個來源找到一致的 NAP 資訊，它更有信心在搜尋結果中推薦你
2. **在地排名**：NAP 一致性是 Local Pack 排名的重要因素
3. **Google Maps 準確性**：不一致的 NAP 可能導致消費者導航到錯誤地址
4. **使用者體驗**：客戶打錯電話、去錯地址 = 失去生意

```
NAP 不一致的實際後果：

案例：一間改名後的餐廳
  網站上：ABC 餐廳（已改名）
  OpenRice 上：XYZ 餐廳（新名）
  Google Maps 上：ABC 餐廳（舊名仍在）
  TripAdvisor 上：ABC / XYZ （混淆）

結果：
  ❌ Google 不確定哪個名稱正確，降低所有版本的排名
  ❌ 客戶在 Google Maps 搜尋 XYZ → 找不到
  ❌ 客戶導航到舊地址（如果搬遷）
  ❌ 新客戶對品牌感到困惑
```

### 學術研究支持

根據 Moz 的 Local Search Ranking Factors 研究，NAP 相關的引用訊號占本地排名因素的 **15-20%**，是僅次於 Google 商家檔案和評論的第三大因素。

## NAP 一致性的四大原則

### 原則 1：精確（Exact）

```
✅ 正確：香港中環皇后大道中 100 號 12 樓 A 室
❌ 錯誤：香港中環皇后大道 100 號 12A（少了「中」和「樓 A 室」的寫法不同）

✅ 正確：+852 1234 5678
❌ 錯誤：1234 5678（缺少區號）

✅ 正確：陳大明牙醫診所
❌ 錯誤：陳大明牙醫（少了「診所」）
```

> **原則：** 選擇一個 NAP 格式，並在任何地方一致使用。不要有時有區號、有時沒有；不要有時寫「樓」、有時寫「/F」。

### 原則 2：完整（Complete）

每次都提供完整的 NAP 三元素。不要只提供電話但沒有地址、或只有名稱但缺少電話。

### 原則 3：統一（Consistent）

- 所有線上平台 → 相同格式
- 所有分店 → 各自的 NAP 獨立且準確
- 搬遷/改名後 → 立即更新所有平台（詳見後續章節）

### 原則 4：本地化（Localized）

```
香港地址格式的標準寫法：

✅ 區域 + 街道 + 門牌 + 大廈 + 樓層 + 單位
   香港中環皇后大道中 100 號 新鴻基大廈 12 樓 A 室

❌ 翻譯成英文格式（例如：Unit A, 12/F, Sun Hung Kai Centre...）
   — 如果你的主要客戶是中文使用者，使用中文地址格式
```

## 什麼是在地引用（Local Citation）？

**在地引用**是指任何在網路上提及你的商家 NAP 資訊的頁面。這些可以是有連結的（Linked Citation）或無連結的（Unlinked Citation）。

```
引用的類型：

1. 結構化引用（Structured Citation）
   在地目錄上的商家檔案頁面
   範例：OpenRice、Yelp、TripAdvisor、Yellow Pages

2. 非結構化引用（Unstructured Citation）
   在新聞報導、部落格文章、社群媒體中提及
   範例：本地報紙報導「陳大明牙醫診所在中環開業」
```

### 引用的 SEO 價值

```
高品質引用 → 增強 Google 對商家資訊的信心
大量的引用 → 提升在地知名度（Prominence）
一致的引用 → 強化 NAP 訊號
在地引用 → 展示與在地社群的連結
```

## NAP 一致性審核步驟

### Step 1：建立你的「正本 NAP」

在開始任何優化之前，先確定你的 NAP 標準格式。

```
我的 NAP 正本：

名稱：陳大明牙醫診所
地址：香港中環皇后大道中 100 號 新鴻基大廈 12 樓 A 室
電話：+852 1234 5678
網站：https://www.chendaming-dental.com.hk
```

### Step 2：進行 NAP 審核

使用以下方法檢查你的 NAP 在網絡上的呈現：

```
方法 A：手動搜尋
  1. Google 搜尋你的商家名稱（含引號）
  2. Google 搜尋你的電話號碼（含引號）
  3. Google 搜尋你的地址（含引號）
  4. 記錄所有出現你 NAP 的頁面
  5. 逐一檢查是否一致

方法 B：使用工具
  → Moz Local（NAP 審核功能）
  → BrightLocal（Citation Tracker）
  → Semrush Listing Management
  → Whitespark Local Citation Finder
```

### Step 3：建立 NAP 不一致清單

```
NAP 審核嘗試表

平台          | NAP 一致？ | 問題說明
--------------|-----------|------------------
Google GBP    | ✅        | 完全一致
網站          | ✅        | 完全一致
OpenRice      | ❌        | 電話缺少區號 (+852)
Yelp          | ❌        | 地址寫法不同（12/F 而非 12 樓）
TripAdvisor   | ❌        | 舊商家名稱（改名前的名稱）
Facebook      | ⚠️        | 缺少門牌號碼
Yellow Pages  | ❌        | 未建立檔案
```

### Step 4：逐一修復

```
修復優先級：
  1. 先修復高權威平台（Google GBP、OpenRice、Yelp 等）
  2. 再修復中低權威平台
  3. 建立尚未存在的檔案（高權威優先）

每個平台的修復步驟：
  1. 登入該平台的商家後台
  2. 更新 NAP 資訊為正本格式
  3. 確認更新成功（登出後搜尋查看）
  4. 記錄更新日期
```

## 商家搬遷 / 改名時的 NAP 管理

### 搬遷流程

```
第 1 步：更新 Google 商家檔案
  → 立即更新新地址
  → 可能需要重新驗證

第 2 步：更新網站
  → 更新網站上所有提及舊地址的地方
  → 更新 LocalBusiness Schema 結構化資料
  → 建立 301 轉址（如果 URL 有包含地址）

第 3 步：更新主要目錄平台
  → OpenRice、Yelp、TripAdvisor、Facebook 等
  → 按優先級順序處理

第 4 步：建立新的在地目錄
  → 在新地址的區域建立新的引用

第 5 步：通知 Google（可選）
  → 如果地址變更較大，可以通過 Google 商家檔案後台通知
```

### 改名流程

```
額外注意事項：
  ✅ 在所有平台使用新名稱
  ✅ 在 Google 商家檔案中保留歷史名稱（如果適用）
  ✅ 關鍵字放在新名稱中（如果符合品牌）：例如「陳大明牙醫診所 - 中環隱形牙套專家」
  ❌ 不要濫加關鍵字（違反 Google 政策）
```

## 常見 NAP 錯誤及解決方案

| 常見錯誤 | 為什麼會發生 | 解決方案 |
|----------|------------|---------|
| 電話格式不一致 | 有時寫 +852，有時省略 | 選擇一個格式並在所有地方使用 |
| 地址縮寫不同 | 「12 樓 A 室」vs「12A」vs「12/F, Unit A」 | 選擇完整寫法 |
| 使用追蹤電話號碼 | 為了追蹤不同渠道使用不同號碼 | **主 NAP 使用一個一致的號碼**，追蹤號碼只用於廣告著陸頁 |
| 舊地址殘留 | 搬遷後未更新所有平台 | 系統性地審核和更新 |
| 共用地址（虛擬辦公室） | 多家公司使用同一地址 | 加上樓層/單位號以區分 |
| 自動生成的檔案 | 目錄平台自動從第三方數據抓取 | 認領並修正這些自動生成的檔案 |

## Schema 結構化資料 — 網站的 NAP 聲明

在你的網站上加入 **LocalBusiness Schema** 是最權威的 NAP 聲明方式。

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Dentist",
  "name": "陳大明牙醫診所",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "皇后大道中 100 號 新鴻基大廈 12 樓 A 室",
    "addressLocality": "中環",
    "addressRegion": "香港島",
    "addressCountry": "HK"
  },
  "telephone": "+85212345678",
  "url": "https://www.chendaming-dental.com.hk",
  "openingHours": "Mo-Fr 09:00-18:00, Sa 09:00-13:00",
  "geo": {
    "@type": "GeoCoordinates",
    "latitude": 22.2810,
    "longitude": 114.1577
  }
}
</script>
```

> **關鍵：** Schema 中的 NAP 必須與你的正本 NAP 100% 一致。

```
每日：
  ☐ 回覆新的 Google 評論（維持活躍度）

每週：
  ☐ 檢查 Google 商家檔案的修改建議（Google 可能會自動修改你的資訊！）

  ☐ 審查所有引用平台的清單（新增/淘汰）
```
