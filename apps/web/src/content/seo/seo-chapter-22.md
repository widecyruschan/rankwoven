## 為什麼內容結構對 SEO 重要？

Google 不只是「閱讀」你的內容——它在嘗試「理解」你的內容。良好的內容結構就像給 Google 一張清晰的地圖，告訴它：哪些是重點、哪些是次要、這些概念之間有什麼關係。

> 結構化的內容 = 更高的閱讀率 + 更長的停留時間 + 更好的排名。

### 香港讀者嘅三個特點

| 特點 | 對內容結構嘅要求 |
|------|------------------|
| **手機主導（七成以上流量）** | 段落要短、表格要可横向捲動、字體 ≥ 16px |
| **中英夾雜閱讀習慣** | 專業術語可中英並列（「結構化資料 Schema」），但要一致唔好亂 |
| **時間寶貴、重視價錢** | 結論先行、價錢放前面（HK$），唔好鋪墊三段先入正題 |

> 香港人網上閱讀節奏極快，一篇冇 TL;DR、冇目錄、冇價錢表嘅長文，跳出率會高得驚人。

## 內容結構的五大原則

### 原則 1：倒金字塔結構

將最重要的資訊放在最前面，讓讀者在前 10 秒就能確認「這篇文章對我有用」。

```
┌─────────────────────────────┐
│  核心結論 / 最重要的答案      │  ← 使用者一進來就看到
├─────────────────────────────┤
│  支持論點、關鍵數據           │  ← 想了解更多的人繼續閱讀
├─────────────────────────────┤
│  詳細解釋、實例、補充          │  ← 深度閱讀者
├─────────────────────────────┤
│  背景資訊、延伸討論           │  ← 可選讀
└─────────────────────────────┘
```

**SEO 意義**：Google 會分析頁面的內容結構，清晰的主次關係有助於 Google 正確評估內容的重要部分。另外，使用者在首屏得到答案會降低跳出率。

**香港版做法**：開頭第一段就要講清「係乜、幾錢、邊度、啱唔啱我」。例如寫「香港搬屋公司收費」，第一段直接畀 HK$ 價錢範圍，再落去解釋點解有價差。

### 原則 2：段落黃金法則

| 面向 | 最佳實踐 |
|------|----------|
| **段落長度** | 3-5 句為佳，不超過 7 句 |
| **一個段落一個觀點** | 一個段落只討論一個核心觀點 |
| **開頭句是主題句** | 每段第一句應該概括該段要講什麼 |
| **避免文字牆** | 長段落用粗體重點、列表、圖片打斷 |

**行動版特別注意**：在手機上，一段 5 句的文字看起來可能像 15 行，極易造成閱讀疲勞。香港七成以上流量嚟自手機，呢點特別致命。

### 原則 3：善用格式化元素

格式化的目標：讓使用者**掃描（Scan）** 時就能抓住重點。

| 元素 | 用途 | 頻率建議 |
|------|------|----------|
| **粗體** | 強調關鍵術語、重要結論 | 每 2-3 段一次 |
| *斜體* | 引用、書名、輕微強調 | 適度使用 |
| `程式碼` | 程式碼、HTML 標籤、指令 | 技術文章中適量 |
| > 引用塊 | 強調關鍵句子、引用專家觀點 | 每 500 字不超過 2 次 |
| 分隔線 | 主要段落之間的視覺分隔 | 每個大主題之間 |
| **價錢表格** | 香港讀者最想睇嘅資訊 | 商業類文章必備 |

### 原則 4：列表與表格——資訊密度最高的格式

#### 無序列表（Bullet Points）

適合：特徵列表、步驟摘要、相關項目。

- 每個列表項目應是一個**完整的觀點**而非殘缺的短語
- 列表項目之間應該是**並列關係**
- 2-8 個項目為佳，過長時考慮分組

#### 有序列表（Numbered List）

適合：步驟教學、排名、時間順序。

1. 每一步是獨立的、可執行的
2. 步驟之間有明確的先後順序
3. 超過 10 步時考慮分組（如「第一階段：準備」）

#### 表格

適合：比較數據、規格對照、功能列表、收費比較。

**表格的 SEO 優勢**：
- Google 常直接將表格內容作為 Featured Snippet
- 高資訊密度的格式，使用者停留時間長
- 適合用 `對象欄 + 屬性列` 的標準格式

**香港版表格示範**（香港讀者最鍾意呢種）：

| 服務 | 收費（HK$） | 包咩 | 唔包咩 |
|------|------------|------|--------|
| 小型搬屋（1-2 房） | 1,280 起 | 包搬運、基本拆裝 | 唔包箱、唔包大型鋼琴 |
| 中型搬屋（3 房） | 2,880 起 | 包搬運、拆裝、包裝物料 | 唔包 storage |
| 寫字樓搬遷 | 報價 | 可安排週末／夜間 | 需實地視察 |

> **價錢透明提醒**：香港消委會指引同行業規管（如地產代理監管局 EAA、證監 SFC、保監局 IA）都要求廣告資料準確。表格入面嘅價錢要寫明「起」定「全包」，同埋係咪「已包其他費用」。

### 原則 5：內容摘要與目錄

#### 文章摘要（TL;DR）

在長篇文章開頭提供一段「文章摘要」或「重點速覽」：

> **📌 本文重點**：喺 5 分鐘內，你會學到點樣優化網站內容結構，包括倒金字塔寫法、段落黃金法則、五大格式化技巧，以及 AI 搜尋時代香港市場嘅內容結構調整策略。

**SEO 價值**：降低跳出率、提升停留時間、適合作為 Featured Snippet 來源。

#### 目錄（Table of Contents）

對於超過 1500 字的長文，在開頭加入可點擊的目錄：

```
## 本文目錄
1. [為什麼內容結構對 SEO 重要？](#1)
2. [內容結構的五大原則](#2)
3. [內容格式化的常見錯誤](#3)
```

**SEO 價值**：
- 產生「跳轉連結」（Jump Links），可能在 SERP 中顯示
- 改善使用者體驗，降低跳出率
- Google 可能將目錄連結顯示在 SERP 中

## 格式化的 SEO 紅線

| 錯誤行為 | Google 的解讀 | 正確做法 |
|----------|-------------|----------|
| 整段用粗體 | 失去了強調的意義 | 只粗體 5-10% 的關鍵詞 |
| 隱藏文字（白色文字、0px） | **嚴重違規**，可能被懲罰 | 永遠不要這樣做 |
| 過度使用 H 標籤 | 結構混亂 | 只用於真正的標題層級 |
| CSS 隱藏內容（display:none） | 可能被視為隱蔽 | 使用手風琴（accordion）設計 |
| 18 區頁只換地名 | 門頁（doorway pages），可能被判低質 | 每區要有獨特內容（案例、價錢、團隊） |

## 常見內容格式對應指南

| 內容類型 | 建議的主要格式 | 輔助格式 |
|----------|---------------|----------|
| 教學 / How-to | 有序列表 + 截圖 | 影片嵌入 |
| 產品評測 | 表格 + 評分卡 | Pros/Cons 列表 |
| 比較文 | 比較表格 + 分段說明 | 結論摘要 |
| 新聞報導 | 倒金字塔 + 引用塊 | 相關連結 |
| 終極指南 | 目錄 + H2/H3 結構 | TL;DR + FAQ |
| 清單 / 推介 | 有序列表 + 簡介 | 表格 + 總結 |
| **香港地區服務頁** | 地區資訊 + HK$ 價錢表 | 實拍相 + GBP 嵌入 + FAQ |
| **香港收費 / 價錢頁** | 價錢表格 + 包咩唔包咩 | 常見問題 + WhatsApp CTA |

## AI 時代的內容結構策略

隨著 AI Overview 和 ChatGPT Search 的興起，內容結構需要適應新的消費方式。

**香港用家使用嘅 AI 工具**：ChatGPT、Gemini、Claude、Perplexity、Microsoft Copilot，以及 Google 嘅 **AI Overviews / AI Mode**。

### 策略調整

1. **明確的問題-答案結構**：AI 更傾向從清晰的 Q&A 結構中提取資訊
2. **段落小標題精準化**：不再使用「介紹」「結論」等模糊標題，改用具體的有資訊量的標題
3. **每個 H2 下的第一段就是核心答案**：AI Overview 偏好從標題後的第一段提取摘要
4. **數據可引用格式**：將統計數據放在獨立的短段落中，方便 AI 直接引用（例如：「2026 年香港 Google 搜尋市佔約 92-95%。」單獨一句）
5. **結構化數據補充**：用 Schema Markup 補充內容結構（見第 24 章）
6. **香港本地來源意識**：國際 AI 仍大量引用 Wikipedia / Reddit / YouTube / LinkedIn 等英文來源；香港等效嘅**連登（LIHKG）、Discuss、Uwants、OpenRice、香港新聞媒體**亦係 AI 可能引用嘅來源。想被引用，就要喺呢啲平台有真實討論同口碑，同時自己網站內容要夠「可引用」（有數據、有日期、有出處）。

### AI 友好的內容結構範本（香港例子）

```html
<h2>狗糧應該幾時換一次？</h2>
<p>一般建議每 3-6 個月逐步調整。轉得太密（少過 1 個月）可能令狗狗腸胃唔舒服。</p>

<h3>逐步換狗糧嘅四個步驟</h3>
<ol>
  <li><strong>第 1-3 日</strong>：混合 25% 新糧 + 75% 舊糧</li>
  <li><strong>第 4-6 日</strong>：混合 50% 新糧 + 50% 舊糧</li>
</ol>

<h3>咩情況唔應該轉狗糧？</h3>
<p>如果狗狗正喺病緊、懷孕，或者處於壓力期（搬屋、屋企加新成員），建議押後轉糧。</p>
```

> **寫畀 AI 睇嘅額外貼士**：數據句要「自包含」——例如寫「香港 Google 市佔約 92-95%（2026 年估算）」，而唔係寫「如上所述，佢嘅市佔超過九成」。AI 摘錄時唔會帶走你上文下理。

## 內容結構檢查清單

- [ ] 文章開頭有關鍵答案或 TL;DR 摘要
- [ ] 段落不超過 7 句，長段落用格式元素打散
- [ ] 每個 H2/H3 標題有具體的資訊量
- [ ] 適度使用粗體強調關鍵點（約 5-10% 的文字量）
- [ ] 列表項目是完整的觀點而非殘缺短語
- [ ] 比較類資訊使用表格（香港價錢要用 HK$）
- [ ] 長文（>1500 字）有目錄
- [ ] 沒有過度格式化或隱藏文字
- [ ] 內容結構對行動裝置友好（短段落、大字體，香港手機讀者為主）
- [ ] Q&A 結構適合 AI 提取資訊（問題用香港人嘅問法：點樣 / 幾時 / 邊度）
- [ ] 價錢資訊寫明「起」定「全包」、係咪已包其他費用
- [ ] 地區頁有獨特內容，唔係淨係換地名

---

## 重點回顧

1. **倒金字塔結構**讓使用者和 Google 快速找到核心答案（香港讀者更加冇耐性）
2. **段落不超過 7 句**，一個段落一個觀點；手機上要更短
3. **格式化元素（粗體、列表、表格）**讓內容可掃描；價錢表格對香港讀者特別有效
4. **TL;DR + 目錄**是長文的 SEO 雙利器
5. **AI 時代需要更清晰的 Q&A 結構**——每個 H2 下第一段就是答案，數據句要自包含
6. 格式化的終極目標不是 SEO，而是**讓使用者讀得下去**
