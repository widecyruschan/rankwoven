## GSC 是什麼？為什麼它是 SEO 最重要的免費工具？

Google Search Console（簡稱 GSC，前身為 Google Webmaster Tools）是 Google 官方提供的網站管理工具。它直接告訴你 Google 如何看待你的網站 — 哪些頁面被收錄、哪些搜尋字詞帶來流量、網站有沒有技術問題。

**GSC 的核心價值：**
- 數據來自 Google 自己，不是第三方估算
- 完全免費
- 即時反映網站與搜尋引擎的互動狀態
- 是發現 SEO 問題的最早警報系統

## 第一步：驗證網站擁有權

### 五種驗證方式

| 方式 | 難度 | 適合對象 | 注意事項 |
|------|------|----------|----------|
| HTML 檔案上傳 | ⭐ | 有 FTP 權限者 | 檔案不能刪，否則驗證失效 |
| HTML 標籤（Meta Tag） | ⭐ | CMS 用戶（WordPress 等） | 加入 head 區塊 |
| DNS 記錄（TXT） | ⭐⭐ | 域名管理者 | 最穩定，推薦使用 |
| Google Analytics | ⭐ | 已安裝 GA4 者 | GA 代碼須有編輯權限 |
| Google Tag Manager | ⭐ | GTM 用戶 | 須有 GTM 發布權限 |

### 推薦流程（DNS 驗證法）
1. 登入 [search.google.com/search-console](https://search.google.com/search-console)
2. 選擇「新增資源」→ 輸入網域（如 `example.com`）
3. 選擇「DNS 記錄」→ 複製 TXT 記錄
4. 到域名 DNS 管理台（如 Cloudflare、GoDaddy），新增 TXT 記錄
5. 回到 GSC 點「驗證」

### 四種資源類型

| 類型 | 格式 | 使用時機 |
|------|------|----------|
| 網域資源 | `example.com` | 跨子網域統一管理（推薦） |
| URL 前綴 — https:// | `https://example.com` | 只追蹤 HTTPS |
| URL 前綴 — http:// | `http://example.com` | 舊 http 網站 |
| URL 前綴 — www | `https://www.example.com` | 含 www 版本 |

> 💡 **推薦使用「網域資源」**，自動涵蓋所有子網域（www、blog、shop）和所有通訊協定（http/https）。

## GSC 核心報表逐個拆解

### 報表一：成效（Performance）— SEO 的心跳圖

這是 GSC 最常用的報表，顯示你的網站在 Google 搜尋中的表現。

#### 四大指標
```
┌──────────┬────────────────────────────────┐
│ 總點擊次數 │ 用戶從搜尋結果點進你網站的次數     │
│ 總曝光次數 │ 你的頁面在搜尋結果中出現的次數     │
│ 平均點擊率 │ 點擊次數 ÷ 曝光次數              │
│ 平均排名   │ 你的頁面在搜尋結果中的平均位置     │
└──────────┴────────────────────────────────┘
```

#### 篩選維度
| 篩選器 | 用途 | 實戰技巧 |
|--------|------|----------|
| 查詢（Queries） | 看哪些關鍵字帶來流量 | 排除品牌關鍵字看純 SEO 成效 |
| 網頁（Pages） | 看哪些頁面表現好 | 找出流量暴跌的頁面 |
| 國家（Countries） | 看流量來自哪裡 | 多語言網站的市場分析 |
| 裝置（Devices） | 手機/電腦/平板 | 手機佔比低 → 行動版可能有問題 |
| 搜尋外觀（Search Appearance） | 含 SERP 功能 | 看產品摘要/FAQ/影片等效果 |
| 日期（Date） | 時間範圍比較 | 對比去年同期排除季節性 |

#### 實戰操作：找出值得優化的頁面

```
步驟 1：選過去 28 天數據
步驟 2：篩選「查詢」排除品牌關鍵字
步驟 3：按「點擊次數」排序，找到流量 Top 10 頁面
       → 這些是你的核心資產，優先維護
步驟 4：按「曝光次數」排序，找到高曝光低點擊頁面
       → CTR 低於 3% → 優化 Title/Meta Description
步驟 5：按「平均排名」篩選 8-20 名
       → 這些是「低垂果實」，稍加優化就能上首頁
```

#### 篩選排名 8-20 的潛力關鍵字

```
GSC → 成效 → 篩選器 → 平均排名 → 自訂 → 8 到 20
→ 按照曝光排序
→ 這就是你的「最容易提升的關鍵字」清單
```

對每個關鍵字，檢查：
1. 著陸頁內容是否充分覆蓋該主題？
2. Title/Meta Description 是否包含該關鍵字？
3. 內部連結是否指向該頁面？
4. 是否需要補充更多深度內容？

### 報表二：網址檢查（URL Inspection）— 單頁診斷

輸入任一 URL，GSC 告訴你：
- ✅ 該頁面是否在 Google 索引中
- ✅ 最後一次爬取日期
- ✅ 是否為標準網頁（Canonical）
- ✅ 行動可用性
- ✅ 結構化資料狀態
- ✅ 是否有任何增強項目（AMP、麵包屑等）

**最實用的功能：**
- **「請求建立索引」按鈕** — 新頁面或更新後，手動請求 Google 重新爬取
- **「查看已爬取的網頁」** — 看 Googlebot 看到的 HTML（不是瀏覽器渲染的）

---

### 報表三：索引（Indexing）— 收錄狀況

#### 頁面索引狀態
```
GSC → 索引 → 頁面
```

**兩種狀態：**
| 狀態 | 圖示 | 說明 |
|------|------|------|
| 已建立索引 | 🟢 | 正常，可以被搜尋到 |
| 未建立索引 | 🟡/🔴 | 需檢查原因 |

#### 常見未索引原因及解法

| 原因 | 嚴重度 | 解法 |
|------|--------|------|
| 找到但未建立索引 | 🟡 | Google 認為品質不夠。改善內容 + EEAT。可能很慢。 |
| 漫遊器已排除（noindex） | 🔴 | 檢查是否誤設了 noindex 標籤 |
| 重複網頁，未選為標準網頁 | 🟡 | 設好 canonical，或內容差異化 |
| 網頁含有 redirect | 🟢 | 正常，轉址頁面本來就不該索引 |
| 404 找不到 | 🔴 | 修復連結或建立 301 轉址 |
| 伺服器錯誤 5xx | 🔴 | 緊急處理伺服器問題 |
| 已檢索 — 目前未建立索引 | 🟡 | Google 看到了但決定不收錄，內容待改善 |

#### 影片頁面索引
如果網站有影片內容，GSC 會單獨顯示影片索引狀態：
- 影片是否被找到
- 縮圖是否被抓取
- 結構化資料是否正確

---

### 報表四：Sitemap — 引導 Google 爬取

```
GSC → 索引 → Sitemap
```

**提交 Sitemap：**
1. 輸入 Sitemap 網址（如 `sitemap_index.xml`）
2. 點「提交」
3. 查看狀態（成功 / 含有錯誤 / 無法讀取）

**Sitemap 健康指標：**
- 已提交的網頁數量 vs 已建立索引的網頁數量
- 比例應 >90%
- 差距過大 → 內容品質可能有問題

---

### 報表五：體驗（Experience）— 用戶體驗監控

#### Core Web Vitals
```
GSC → 體驗 → Core Web Vitals
```

顯示每個 CWV 指標（LCP、INP、CLS）的通過狀況：
| 狀態 | 說明 |
|------|------|
| 網址不良 | 該頁面 CWV 不達標 |
| 網址需要改善 | CWV 介於及格線邊緣 |
| 網址良好 | CWV 全部通過 |

> 💡 點進「不良網址」可以看到影響多少頁面、按相似問題分組（如同一模板的產品頁面）。

#### HTTPS
檢查網站是否有非 HTTPS 的頁面被索引。

#### 行動可用性（Mobile Usability）
- 文字太小
- 點擊元素間距不足
- 內容超出螢幕寬度
- viewport 未設定

### 報表六：手動操作與安全問題

```
GSC → 安全性與手動操作
```

**手動操作（Manual Actions）：** Google 審查人員對網站進行的人工懲罰。
- 最常見：非自然連結（Unnatural Links）、內容貧乏（Thin Content）
- 需要提交「重審要求」來解除

**安全性問題：**
- 網站被駭客入侵
- 惡意軟體（Malware）
- 社交工程攻擊（釣魚頁面）
- Google 會主動通知你

## 進階操作：GSC 的七個實戰技巧

### 技巧一：比較日期範圍找出問題

```
GSC → 成效 → 日期 → 比較
```

設定「過去 28 天」vs「前 28 天」，看：
- 哪些關鍵字排名大幅下滑？
- 哪些頁面流量驟降？
- 新發布的內容有沒有開始獲得曝光？

### 技巧二：正則表達式過濾查詢

在查詢篩選器中，選擇「自訂（regex）」，支援正則表達式：

```
// 找出所有問句形式的搜尋（適合內容創作靈感）
(怎麼|如何|什麼|為什麼|哪裡|何時)

// 找出含價格意圖的搜尋
(便宜|價格|多少錢|費用|優惠|特價)

// 找出比較型搜尋
(vs|比較|推薦|哪個好|排行|評價)
```

### 技巧三：導出數據到 Google Sheets

```
GSC → 成效 → 右上角「匯出」→ Google Sheets
```

導出後可以：
- 用試算表公式做更深度的分析
- 合併多期數據看長期趨勢
- 與 GA4 數據交叉比對

### 技巧四：監控品牌 vs 非品牌流量變化

每月的固定儀式：
```
步驟 1：篩選包含品牌名的查詢 → 記錄總點擊次數
步驟 2：篩選排除品牌名的查詢 → 記錄總點擊次數
步驟 3：計算比例，追蹤月變化
```

如果非品牌流量比例持續下降：
- 內容策略可能需要調整
- 競爭對手可能在搶走你的非品牌關鍵字

### 技巧五：發現蠶食關鍵字

```
GSC → 成效 → 按「查詢」分組 → 篩選特定關鍵字 → 按「網頁」維度查看
```

如果同一關鍵字出現 3+ 個頁面都有排名：
- 表示內部競爭（蠶食）
- 需要合併內容或設定 canonical

### 技巧六：使用 URL Inspection API 批量檢查

GSC 的限制是單次只能檢查一個 URL，但你可以用 API 批量處理：

```python
# 概念示範：批量檢查 URL 狀態（需要設定 GSC API）
urls_to_check = [
    "https://example.com/page1",
    "https://example.com/page2",
    # ...
]
# 使用 searchconsole.query.inspect() 批量查詢
```

> 實務上可以用 Screaming Frog 整合 GSC API 來做批量分析，比手動逐個檢查有效率得多。

### 技巧七：找出低 CTR 的高排名頁面

```
步驟 1：成效報表 → 篩選平均排名 1-5
步驟 2：按照 CTR 由小到大排序
步驟 3：找出 CTR 明顯低於位置基準的關鍵字（如第 3 名但 CTR <5%）
```

低 CTR 的可能原因：
1. **Title 不夠吸引人** — 加入數字、年份、利益點
2. **Meta Description 太普通** — 重寫為行動導向
3. **SERP 功能搶走點擊** — AI Overviews 或 Featured Snippet 佔據了注意力，考慮結構化資料優化
4. **品牌辨識度低** — 用戶傾向點擊認識的品牌，長期累積品牌權威

## GSC 管理多網站

如果你管理多個網站，GSC 提供：
- **資源管理**：在同一個 GSC 帳號下切換不同網站
- **使用者與權限**：可以設定「擁有者」「完整權限」「受限權限」
- **驗證擁有者**：可將驗證 Token 用於跨平台工具（如 Data Studio、Ahrefs）

## GSC vs GA4：分工明確

| 維度 | GSC | GA4 |
|------|-----|-----|
| 數據類型 | 搜尋行為（曝光、點擊、排名） | 網站行為（瀏覽、停留、轉換） |
| 時間視角 | 搜尋前 → 點擊前 | 點擊後 → 離開後 |
| 關鍵功能 | 關鍵字排名、索引狀態、技術問題 | 流量來源、用戶行為、轉換漏斗 |
| 互通性 | 可連結到 GA4，數據互通 | 可連結到 GSC，在 GA4 看搜尋報表 |

**最佳實踐：** 將 GSC 連結到 GA4，這樣可以在 GA4 中看到「搜尋查詢」報表，結合用戶行為數據一起分析。
