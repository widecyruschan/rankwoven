## PageRank 是什麼？

**PageRank** 是 Google 創始人 Larry Page 在史丹佛大學開發的演算法，也是 Google 搜尋引擎的原始核心。它的基本邏輯：

> 一個頁面的重要性，取決於有多少其他頁面連結到它，以及這些連結頁面本身有多重要。

### 簡單的理解模型

```
假設整個網路只有 4 個頁面 A、B、C、D：

  A ──→ B
  │      │
  ↓      ↓
  C ←── D

A 連結到 B 和 C → A 的 PageRank 分配給 B 和 C
B 連結到 D → B 的 PageRank 傳遞給 D
D 連結到 C → D 的 PageRank 傳遞給 C
C 沒有連結出去 → C 的 PageRank 不傳遞（阻尼）
```

---

## PageRank 的核心機制

### 1. 連結 = 投票

每個從頁面 A 到頁面 B 的連結，都是 A 對 B 的「投票」。

### 2. 投票的權重不同

```
來自高 PageRank 頁面的連結  >  來自低 PageRank 頁面的連結
來自 nytimes.com 的連結    >  來自不知名部落格的連結
```

### 3. 投票的價值被稀釋

一個頁面的 PageRank 會平均分配給它所有指向外部的連結。頁面上的連結越多，每個連結分到的 PageRank 越少。

```
頁面有 PR = 10，連結到 5 個頁面：
  每個頁面獲得 PR ≈ 2

頁面有 PR = 10，連結到 100 個頁面：
  每個頁面獲得 PR ≈ 0.1
```

> **這就是為什麼「連結越多不一定越好」——來自一個只有 2 個外部連結的頁面的連結，價值遠高於來自一個有 200 個外部連結的頁面。**

### 4. Nofollow 連結不傳遞 PageRank

```html
<!-- 這個連結傳遞 PageRank -->
<a href="https://example.com">推薦網站</a>

<!-- 這個連結不傳遞 PageRank -->
<a href="https://example.com" rel="nofollow">推薦網站</a>
```

## PageRank 在 2026 年的地位

### PageRank 還重要嗎？

**重要。** 雖然 Google 不再公開 PageRank 分數（2016 年停止公開 Toolbar PageRank），但 PageRank 仍然是 Google 排名演算法的核心組成部分。

Google 的 Gary Illyes 在 2024 年確認：「PageRank 仍然是我們的排名訊號之一。」

### PageRank 的現代演進

| 時代 | PageRank 的角色 |
|------|----------------|
| 1998-2005 | 最重要的排名因素 |
| 2005-2012 | 與其他因素（內容、使用者體驗）並重 |
| 2012-2020 | 重要性下降但仍是核心，Penguin 演算法清理操縱行為 |
| 2020-2026 | 基於 AI 的 RankBrain / BERT / MUM 補充 PageRank，但連結分析仍不可替代 |

### 現代 SEO 中 PageRank 的三個角色

```
1. 發現（Discovery）
   → Google 透過連結發現新頁面
   → 沒有內部或外部連結的頁面很難被發現

2. 權威評估（Authority Assessment）
   → 被越多權威頁面連結 = 頁面越權威
   → 這是 PageRank 最核心的功能

3. 爬取優先級（Crawl Prioritization）
   → 高 PageRank 的頁面被 Google 爬取得更頻繁
   → 這影響 Crawl Budget 的分配
```

## 連結權重的傳遞機制

### Link Juice（連結果汁）的概念

**Link Juice** 是 SEO 社群的非正式術語，用來描述透過超連結傳遞的「排名權重」。雖然不是官方術語，但直觀地表達了 PageRank 的流動概念。

### Link Juice 傳遞的規則

```
規則 1：每個頁面有固定量的 Link Juice
規則 2：Link Juice 透過 dofollow 連結傳遞
規則 3：傳遞的量 = 頁面總量 ÷ 頁面上的連結數
規則 4：Nofollow / UGC / Sponsored 連結不傳遞
規則 5：301 重定向傳遞大部分（90-99%）Link Juice
規則 6：302 重定向不傳遞 Link Juice
規則 7：Canonical 標籤集中 Link Juice
```

### 內部連結的 PageRank 分配策略

你可以透過內部連結的結構來控制 PageRank 在網站內的流動方向：

```
首頁（Highest PR）
  ├─ 導覽列連結 → 主要分類頁（High PR）
  │     ├─ → 重要產品頁（Medium PR）
  │     └─ → 次要產品頁（Low PR）
  └─ 文章列表 → 個別文章（依連結數分配 PR）

策略：
→ 首頁連結到最重要的頁面
→ 用內部連結把權重從「強頁面」導向「需要排名提升的頁面」
→ 使用 nofollow 阻止權重流向不重要的頁面（如登入頁、購物車）
```

## PageRank 塑形（Pagerank Sculpting）

### 傳統 PageRank Sculpting（2009 年前）

早期 SEO 的做法：用 nofollow 阻止權重流向不重要頁面，讓更多權重集中到重要頁面。

```html
<!-- 傳統做法 -->
<a href="/login" rel="nofollow">登入</a>
<a href="/cart" rel="nofollow">購物車</a>
<a href="/important-page">重要頁面</a>  ← 獲得更集中的 PageRank
```

### 現代 PageRank Sculpting（2009 年後）

2009 年，Google 的 Matt Cutts 宣布：nofollow 的 PageRank 不會被「重新分配」，而是**蒸發**。這改變了 PageRank Sculpting 的邏輯。

```
傳統模型（2009 年前）：
  頁面有 10 PR，10 個連結，其中 5 個 nofollow
  → 5 個 dofollow 連結各獲得 2 PR

現代模型（2009 年後）：
  頁面有 10 PR，10 個連結，其中 5 個 nofollow
  → 10 PR ÷ 10 連結 = 每個連結分到 1 PR
  → 5 個 dofollow 連結各獲得 1 PR
  → 5 個 nofollow 的 PR 蒸發（不傳遞）
  → 總共只傳遞了 5 PR，而不是 10 PR
```

### 現代的權重集中方法

不再使用 nofollow 來集中權重，而是用**結構設計**：

```
✅ 好的做法：改變連結結構
  - 在主要導覽中只放重要頁面
  - 將次要連結放在頁尾或側邊欄
  - 減少每個頁面上的總連結數量

❌ 不好的做法：大量使用 nofollow
  - 反而損失了可以再利用的 PR
  - 對使用者體驗沒有幫助
```

## 計算與衡量 PageRank 的現代工具

雖然 Google 不再公開 PageRank 分數，但第三方工具提供了近似的指標：

| 工具 | 指標 | 衡量什麼 |
|------|------|----------|
| **Ahrefs** | DR（Domain Rating） | 網站整體的反向連結強度（0-100） |
| **Ahrefs** | UR（URL Rating） | 單一頁面的反向連結強度（0-100） |
| **Moz** | DA（Domain Authority） | 網站整體的排名潛力（0-100） |
| **Moz** | PA（Page Authority） | 單一頁面的排名潛力（0-100） |
| **Semrush** | AS（Authority Score） | 網站整體品質和 SEO 表現（0-100） |

### 如何解讀這些分數

| 指標用途 | 正確用法 | 錯誤用法 |
|----------|---------|----------|
| **競品對比** | 「我的 DR 30，對手 DR 50，我需要改善連結建設」 | 「DR 50 的網站一定比 DR 30 排名好」 |
| **趨勢追蹤** | 「我的 DR 從 20 成長到 35，表示連結策略有效」 | 「我需要讓 DR 達到 100 才算成功」 |
| **連結機會評估** | 「這個網站 DR 高，獲取連結的價值較高」 | 「我只接受 DR > 50 的網站的連結」 |

> **注意：** 這些都是第三方估算，不是 Google 的真實指標。用於相對比較和趨勢追蹤，而非絕對判斷。

## PageRank 思維的 SEO 應用

### 應用 1：首頁內部連結策略

首頁通常有最高的 PageRank。確保首頁連結到你最重要的頁面。

```
首頁的連結策略：
  ☑ 連結到核心商業頁面（產品/服務）
  ☑ 連結到最重要的部落格內容
  ☑ 連結到「關於我們」和「聯絡我們」
  ☐ 不要連結到隱私政策、條款等低價值頁面（放在頁尾）
```

### 應用 2：孤兒頁面檢測

孤兒頁面 = 被 Google 索引但沒有任何內部連結指向它的頁面。這類頁面無法從你網站的其他頁面獲得 PageRank。

```
每月檢查：
→ Screaming Frog 爬取全站
→ 找出未被任何內部連結指向的頁面
→ 從相關頁面加入連結
```

### 應用 3：連結衰減管理

隨著網站增長，新頁面往往只獲得少數內部連結，PageRank 分配越來越薄。

```
解決方案：
→ 內容發布後，從高 PR 舊頁面加入連結到新頁面
→ 使用「相關文章」或「熱門文章」區塊來循環分配 PR
→ 定期審查確保每個重要頁面有不少於 3 個內部連結
```

### 應用 4：重定向的 PR 保留

301 重定向保留約 90-99% 的 PageRank。當你刪除或合併頁面時，永遠使用 301 將舊 URL 的 PR 保留到新 URL。

| 任務 | 說明 |

| ☐ 保持每個頁面連結數合理 | 一個頁面上不要有數百個連結 |
| ☐ 301 重定向保留 PR | 刪除頁面時永遠做 301 |
