## 內容維護比內容創作更重要

許多網站經營者陷入一個迷思：SEO = 不斷產出新內容。但現實是：

> 維護 100 篇高品質內容遠比擁有 500 篇過時內容更有 SEO 價值。
>
> 香港版講法：與其每個月寫 10 篇新文，不如搞清楚你嗰 100 篇舊文入面，邊 20 篇只要改改價錢同年份就可以即刻上位。

本章介紹兩種相輔相成的策略：**內容更新（Content Refresh）** 讓有潛力的舊內容煥發新生，**內容修剪（Content Pruning）** 將拖累網站品質的低效內容移除。

## 內容更新（Content Refresh）

### 為什麼舊內容會失去排名？

Google 偏愛「新鮮」的內容，尤其在以下類型的主題：

| 主題類型 | 新鮮度敏感度 | 香港例子 |
|----------|------------|---------|
| 新聞與時事 | 🔥🔥🔥🔥🔥 | 「2026 年 Google 演算法更新」「八號風球安排」 |
| 工具與產品評測 | 🔥🔥🔥🔥 | 「2026 香港網店平台推介」「寬頻邊間好」 |
| 技術教學 | 🔥🔥🔥 | 「WordPress 6.5 SEO 設定指南」 |
| 香港價錢 / 收費類 | 🔥🔥🔥🔥 | 「香港註冊有限公司費用」「會計軟件月費」 |
| 香港法規類 | 🔥🔥🔥🔥 | 「免稅額一覽」「強積金供款上限」 |
| 定義與概念 | 🔥🔥 | 「什麼是 SEO？」 |
| 歷史事件 | 🔥 | 「Google Panda 演算法的歷史」 |

> **香港特別提醒：** 「價錢 / 收費 / 法規」呢兩類內容喺香港嘅衰退速度特別快——政府收費表年年改、供應商月費季季變。一篇 2023 年寫嘅「香港開公司費用」，到 2026 年如果冇更新，入面嘅數字全部錯晒，讀者一睇就會走。呢類文章要列為「最高優先更新」。

### 內容衰退的典型訊號

```
📉 排名從第 3 名緩慢滑落到第 9 名
📉 點擊率（CTR）低於 SERP 平均值
📉 頁面停留時間明顯下降
📉 反向連結增長停滯甚至減少
📊 競爭對手的更新日期比你新
💰 文中嘅 HK$ 價錢 / 政府收費已經變咗
🏛️ 文中引用嘅香港法規 / 免稅額 / 牌照要求已經改咗
🏪 文中提到嘅分店 / 平台 / 服務已經停咗
```

### 內容更新的四級分類法

| 級別 | 適用情況 | 做法 | 時間投入 |
|------|---------|------|----------|
| **Tier 1：小幅刷新** | 數據/日期過時，但主體內容仍然準確 | 更新年份、HK$ 價錢、失效連結、標記更新日期 | 30 分鐘 |
| **Tier 2：中幅升級** | 內容結構可接受，但缺乏深度和新資訊 | 增加新章節、補充最新香港案例、加入新工具/方法、回答新 PAA 問題 | 2 小時 |
| **Tier 3：大幅改寫** | 內容方向正確但品質落後於競爭對手 | 重寫 50%+ 內容、新增原創數據/截圖、重新設計結構、>30% 的字數增加 | 5 小時 |
| **Tier 4：合併或重定向** | 多篇相關主題的淺薄內容 | 合併為一篇深度 Pillar 內容，舊 URL 301 到新 URL | 8 小時 |

### 內容更新的實戰流程

```
第 1 步：識別候選文章
  → 在 GSC 中找出以下頁面：
    - 排名在第 6-20 名的文章（最有升級潛力）
    - 流量下降超過 30% 的頁面
    - 曾經排過前 3 名但已下滑的頁面
  → 香港專屬：另外篩出所有含 HK$ 價錢 / 政府收費 / 法規嘅頁面，
    用 Screaming Frog 自訂擷取（Custom Extraction）搵出嚟，優先處理

第 2 步：競爭對手分析
  → 針對每篇候選文章：
    - 分析目前香港 SERP 排名前 3 嘅內容有咩你冇？
    - 佢哋嘅主題覆蓋度、多媒體、更新日期？
    - 有冇大平台（香港01 / OpenRice / 28Hse）搶咗位？

第 3 步：確定更新級別
  → 依照「四級分類法」決定每篇文章的更新程度

第 4 步：執行更新
  → 按優先級分批執行（先處理流量最高的）

第 5 步：追蹤效果
  → 更新後 4-8 週觀察排名和流量變化
```

### 更新後必須做的事

```
☐ 更新文章的「最後更新日期」顯示
☐ 在 GSC 中請求重新索引（Request Indexing）
☐ 同步去 Bing Webmaster Tools 提交（覆蓋 Yahoo 香港 + ChatGPT/Copilot）
☐ 如果 URL 有變，設定 301 重定向
☐ 如果標題大幅變更，確認 SERP 顯示是否正確
☐ 更新文中所有 HK$ 價錢，並標示「截至 YYYY年M月」
☐ 檢查引用嘅香港法規 / 政府收費係咪最新
☐ 確認文中提到嘅分店 / 平台 / 服務仲喺度
☐ 監控排名變化至少 4 週
```

## Content Pruning（內容修剪）

### 什麼是 Content Pruning？

Content Pruning 是**系統性地識別並處理網站上表現不佳的內容**，以提升整體網站品質的過程。

> **比喻：** 花園需要修剪枯枝才能讓健康的植物長得更好。網站內容也一樣——修剪掉「枯枝」內容，讓 Google 的 Crawl Budget 集中在你的優質內容上。
>
> 香港版比喻：好似執屋咁——間屋得 400 呎，擺滿舊嘢，好嘢都冇位擺。

### 哪些內容需要修剪？

#### 🔴 明確應修剪的內容

| 類型 | 判斷標準 | 處理方式 |
|------|---------|----------|
| **零流量內容** | 12 個月內沒有任何自然流量 | 刪除或合併 |
| **過時內容** | 資訊已不準確且無法更新 | 刪除（410）或更新 |
| **Thin Content** | 少於 300 字且無獨特價值 | 合併到相關文章，301 重定向 |
| **重複內容** | 與其他頁面內容高度重複 | 301 到 canonical 頁面 |
| **不相關內容** | 與網站主題無關的舊文章 | 刪除或移到子網站 |
| **已結束嘅活動頁** | 舊嘅節日推廣頁（例如 2023 雙十一） | 301 去最新活動頁或分類頁 |
| **已結業分店頁** | 分店已經執笠 | 301 去就近分店或分店總覽頁 |

#### 🟡 需要評估的內容

| 類型 | 評估標準 | 處理方式 |
|------|---------|----------|
| **低流量但有反向連結** | 每月 < 10 次點擊，但有高品質外連 | 改善內容，保留 URL |
| **低流量但排名不錯** | 排前 10 但點擊率低 | 優化 Title Tag 和 Meta Description |
| **中等流量但內容過時** | 每月有流量但資訊需更新 | 優先排入內容更新計畫 |

### Content Pruning 的三種處理方式

#### 1. 刪除（Delete）→ 返回 410 Gone
適用於：完全無價值、無流量、無反向連結、無法更新的內容。

```
✅ 好處：立即釋放 Crawl Budget
⚠️ 注意：確保該頁面沒有被外部連結
```

#### 2. 合併（Merge）→ 301 Redirect
適用於：多篇淺薄文章可整合為一篇深度的 Pillar 內容。

```
Before：
  /blog/seo-tip-1  （200 字，低流量）
  /blog/seo-tip-2  （300 字，低流量）
  /blog/seo-tip-3  （250 字，低流量）

After：
  /blog/seo-complete-guide  （2,500 字，整合以上三篇的精華）
  三個舊 URL 全部 301 → /blog/seo-complete-guide
```

**香港例子（分店頁合併）：**
```
Before：
  /branches/tsim-sha-tsui   （150 字，只係地址電話，零流量）
  /branches/mong-kok        （150 字，同上）
  /branches/causeway-bay    （150 字，同上）

After：
  /branches   （一頁分店總覽：地圖 + 各區地址 + 交通 + 營業時間 + 每間分店獨特相片）
  三個舊 URL 全部 301 → /branches
```

**香港例子（舊平台比較文）：**
```
Before：
  /blog/2021-hk-ecommerce-platforms   （2021 年寫，平台收費全過時）
  /blog/2022-hk-ecommerce-platforms   （2022 年寫）
  /blog/2023-hk-ecommerce-platforms   （2023 年寫）

After：
  /blog/hk-ecommerce-platforms   （一篇常青文，每年更新，URL 唔含年份）
  三個舊 URL 全部 301 → /blog/hk-ecommerce-platforms
```

> **好處：** 唔使年年開新 URL，權重全部累積落同一頁，排名越做越穩。

#### 3. 改善（Improve）→ 保留 URL
適用於：有潛力但內容不足的頁面。排入內容更新計畫，而不是刪除。

### Content Pruning 的執行流程

```
第 1 步：內容盤點（Content Audit）
  → 導出全站所有頁面的清單（URL + 流量 + 排名 + 字數 + 反向連結）
  → 工具：Screaming Frog + GSC API + Google Analytics

第 2 步：分類與評分
  → 將每個頁面分為三類：
    ✅ 保留（Keep）：表現良好
    🔄 改善（Improve）：有潛力，需要更新
    ❌ 修剪（Prune）：無價值，應該處理

第 3 步：制定行動方案
  → 對於「修剪」類頁面：
    - 確定處理方式（刪除/合併/301）
    - 檢查外部連結（保留有外部連結的頁面）
    - 建立舊 URL → 新 URL 的 301 對照表
  → 香港專屬檢查：
    - 呢個 URL 有冇被放落 Google 商家檔案 / OpenRice / HKTDC / Facebook 專頁？
    - 有冇印喺卡片、餐牌、宣傳單張嘅 QR code？
    - 有冇喺 LIHKG / 連登 / 社團被貼過？

第 4 步：批次執行
  → 分批執行，不要一次處理整個網站
  → 每批 10-20 個頁面，觀察效果後再繼續

第 5 步：監控影響
  → 檢查 GSC 的索引狀態
  → 監控整體流量變化
  → 確認未引入新的 404 錯誤
```

### Content Pruning 的常見錯誤

| 錯誤 | 後果 | 正確做法 |
|------|------|----------|
| 一次修剪太多頁面 | 流量驟降，無法判斷原因 | 分批進行，每批 10-20 頁 |
| 刪除有外部連結的頁面 | 失去寶貴的連結權重 | 先檢查反向連結，有的話改善而非刪除 |
| 全部導向首頁 | Google 視為 Soft 404，無 SEO 價值 | 301 到最相關的替代頁面 |
| 不更新 Sitemap | 已刪除的 URL 仍在 Sitemap 中 | 同步更新 Sitemap（GSC + Bing WMT） |
| 忽略內部連結 | 網站內部出現大量 404 | 更新內部連結指向新位置 |
| 忽略本地平台舊連結 | OpenRice / GBP / FB 專頁嘅 link 變死link | 修剪後同步更新本地平台資料 |
| 刪咗仲有廣告指住嘅頁 | 廣告浪費錢 + 登陸頁錯誤 | 修剪前檢查 Google Ads / Meta Ads 登陸頁 |

## 建立內容維護的節奏

### 每月內容維護排程

| 週次 | 任務 |
|------|------|
| **第 1 週** | 審查上月發布的新內容表現 |
| **第 2 週** | 挑選 3-5 篇需要 Tier 1/2 更新的文章 |
| **第 3 週** | 執行內容更新（重點：HK$ 價錢 + 失效連結） |
| **第 4 週** | 審查流量下降的頁面，決定修剪或更新 |

### 每季內容大審計

```
☐ 導出所有頁面的過去 12 個月流量數據
☐ 識別流量下降 >30% 的頁面
☐ 識別零流量頁面
☐ 評估每頁的內容品質和更新需求
☐ 制定下一季的更新和修剪計畫
☐ 執行一批 Content Pruning（如有需要）
```

### 香港季節性更新日曆

| 時間 | 要更新嘅內容 |
|------|-------------|
| **每年 2-3 月** | 稅季相關文（報稅表、免稅額、扣稅）—— 趕喺 4 月派表前完成 |
| **每年 12 月 - 1 月** | 所有「2026 → 2027」嘅年度文章換年 |
| **每年 3 月 / 9 月** | 檢查政府收費表（公司註冊處、運輸署等）相關文章 |
| **大型節日前 4-6 週** | 節日攻略文（農曆新年、書展、雙十一、聖誕） |
| **Google 演算法更新後 2 週** | 檢查排名大跌嘅頁面 |

## 更新 vs 新建：資源分配策略

一個常見的問題：我應該花時間更新舊文章還是寫新文章？

| 情境 | 建議策略 | 理由 |
|------|---------|------|
| 網站少於 50 篇文章 | 60% 新建 / 40% 更新 | 先建立內容基礎 |
| 50-200 篇文章 | 50% 新建 / 50% 更新 | 平衡成長與維護 |
| 200-500 篇文章 | 40% 新建 / 60% 更新 | 維護既有資產更有效率 |
| 500+ 篇文章 | 30% 新建 / 70% 更新 | 內容修剪 + 更新是高槓桿活動 |

> **核心邏輯：** 網站越大，未維護的「內容債務」越多。更新舊內容的 SEO 回報往往比從零寫一篇新文章更快、更穩定。
>
> **香港市場加乘：** 香港市場細、關鍵字量低，「同一個題目開 5 篇」嘅效益遠低於「將 5 篇合成一篇做強」。所以香港網站應該比一般建議**更早開始偏向更新**——例如得 30 篇文嘅香港網站，就已經值得用 50/50 分配。
